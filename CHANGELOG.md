# Changelog

Notable changes to `@kleros/ui-components-library`, for the apps that consume it. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and versions follow [Semantic Versioning](https://semver.org/).

Every pull request that changes what a consumer sees adds its entry under **Unreleased**. A release moves those entries under a new heading with the version and date and leaves **Unreleased** in place, empty, for the next changes.

## [Unreleased]

## [3.11.0] - 2026-11-10

### Breaking changes

None. Every new prop is optional and keeps today's default. The `tailwindcss` and `@tailwindcss/postcss` peer ranges
stay `^4.0.11`, enough for the core; the kit and the lint preset need Tailwind 4.1.17 or later (README, Peer
Dependencies), and `kleros-ui check` says so in an app on Tailwind before 4.1.

### Added

- LinearProgress: `width` is optional. Without it the bar fills its container, a flex row included, and follows it when it resizes; in a parent sized to its content (`w-fit`), pass `width`. A number keeps today's fixed width.
- CircularProgress: a `tone` prop (`success`, `warning`, `error`, `info`, `neutral`, `accent`) sets the fill colour at every value. Without it the fill stays blue and turns green at 100%. The `CircularProgressTone` type is exported.
- Card: a `fluid` prop sizes the card to its content and its container instead of the fixed 328×200.
- Modal: a `fluid` prop sizes the dialog to its content, up to the viewport, instead of the fixed 328×200.
- Types: the prop and item types are exported under unique names (for example `TabsItem`), except the props of `CustomRadioItem` and `RadioIndicator` and the items of `CustomAccordion`, `CustomRadio` and `DraggableList`. The published declarations keep their JSDoc, with examples on `Button`, `DropdownSelect`, `BigNumberField` and `Tabs`. They are re-exported with a plain `export *`, so TypeScript before 5.0 reads the declarations with `skipLibCheck` off.
- Tag: `children` render instead of `text`, which stays required and becomes the accessible name. A `toggle` prop announces `active` as `aria-pressed`. `children` that render nothing (`undefined`, `null`, `""`, a boolean, or an array or empty fragment of those) fall back to `text`.
- Tooltip: a `content` prop takes rich content, which replaces `text`. The `wrapperProps.role` option (default `button`) is documented.
- TextField: `labelContent` and `description` take rich content for the label and the description slot. `label` and `message` stay strings, and the rich prop wins when both are set. A rich prop that renders nothing (`undefined`, `null`, `""`, a boolean, or an array or empty fragment of those) falls back to the plain prop; `0` renders as 0, as in React.
- TextArea: `labelContent` and `description` take rich content for the label and the description slot. `label` and `message` stay strings, and the rich prop wins when both are set. A rich prop that renders nothing (`undefined`, `null`, `""`, a boolean, or an array or empty fragment of those) falls back to the plain prop; `0` renders as 0, as in React.
- NumberField: `labelContent` and `description` take rich content for the label and the description slot. `label` and `message` stay strings, and the rich prop wins when both are set. A rich prop that renders nothing (`undefined`, `null`, `""`, a boolean, or an array or empty fragment of those) falls back to the plain prop; `0` renders as 0, as in React.
- Breadcrumb: an item with `href` renders a link (react-aria `Link`) instead of a button. The last item has `aria-current="page"`. `as="nav"` with an `aria-label` (default "Breadcrumb") makes it a navigation landmark; the default stays a `div`.
- Button: a `title` prop that renders as the native tooltip, a `ref` to the `<button>`, and `children` that render instead of `text`, which stays required and names the button (a caller's `aria-label` wins), so icon-only buttons have a name. `children` that render nothing (`undefined`, `null`, `""`, a boolean, or an array or empty fragment of those) fall back to `text`.
- Copiable: the copy button has an accessible name (`info`, default "Copy"), and a visually hidden live region announces "Copied" or "Copy failed". New `onCopy` and `onCopyError` callbacks, and `feedbackDuration` (default 2000 ms). A failed clipboard write is no longer swallowed.
- `cn`: the class-name helper the components use (clsx plus tailwind-merge) is exported, so an app's `className` can override a default class.
- Kit: `@kleros/ui-components-library/kit` adds app-level pieces built only from the library's components and theme tokens: layout (`Stack`, `Inline`, `Grid`, `Section`, `Page`, `FormStack`), loading, empty and error states (`Skeleton`, `Spinner`, `EmptyState`, `InfoCard`, `ErrorState`, `QueryState`), data (`StatCard`, `AddressDisplay`, `TokenAmount`, `DataTable`, `KeyValueList`, `Sparkline`), `StatusBadge`, forms (`FormField`, `WizardShell`), `Countdown`, and app pieces (`ExternalLink`, `HelpTooltip`, `ThemeToggle`, `ChainGuard`), with `useCountdown`, `useDarkMode`, `applyInitialTheme`, `shortenAddress`, `formatAmount`, `parseUnits`, `toneClasses`, `readToken` and `cn`. Its classes reach an app through the Tailwind entry's `@source` line (README, Setup), which needs Tailwind 4.1 or later: before 4.1 that line can scan none of the kit (`agent/AGENTS.md`, "Existing apps"). The starter and the lint preset's plugin use 4.1.17 or later. Under `"moduleResolution": "node"`, TypeScript finds its types through `typesVersions`.
- Kit props: `QueryState` takes `errorTitle` and `isPending` (a query that has not started, a disabled one included, shows the skeleton, not the empty state), shows the error only when there is no data, `undefined` or `null` (a failed refetch keeps the loaded rows), and its `empty.action`, like `EmptyState`'s `action`, is `{ text, onPress }` (a small Button) or a node, shown under the description. `DataTable` columns take a `width` (px or a CSS width) for their header cell, so they can keep their place while the table loads. `ChainGuard` takes `isConnecting`, which shows a spinner instead of the connect or switch prompt. `TokenAmount` shows a non-zero amount too small for `maxFractionDigits` as `<0.0001` at the default 4 digits (`<0.01` for 2). `AddressDisplay`'s explorer link is a "↗" beside the address, outside the tooltip's trigger. `InfoCard` shows an icon per variant and gives screen readers the variant word first. `useDarkMode` and `ThemeToggle` follow the `dark` class on `<html>`, whoever changes it. `Countdown` shows the units in a row from the largest one, zeros kept (`1d 0h 3m`). `FormField` gives a single control child (an input, select, textarea or button, an element with a `role`, or a component that passes the props on) its label, description and error (`aria-labelledby`, `aria-describedby`, `aria-invalid`); a Fragment or a wrapper `div` is left as it is. `parseUnits` throws on `decimals` that are not a whole number; a digit string such as `"6"` counts as that number, and an omitted or `undefined` `decimals` means 18. `StatusBadge` text is PrimaryText in every tone, so it meets WCAG AA on the tone's fill in both themes; the tone shows in the fill and the dot, and `dot` defaults to true (`dot={false}` hides it). `toneClasses` returns the same classes. `ExternalLink`'s trailing arrow is hidden from screen readers, so the link's name is its text. `WizardShell`'s example catches a rejected `onSubmit` and shows it in an `AlertMessage` on the last step.
- Lint preset: `@kleros/ui-components-library/eslint`, for an ESLint flat config (ESLint 9 or later, or 8.26 or later, where `ui:check` and `ui:baseline` turn on ESLint 8's flat-config mode with `ESLINT_USE_FLAT_CONFIG`; in an app's own config, ESLint 8 before 8.57 finds only `eslint.config.js`), holds an app's code to the library's look. It reports a raw control where the library has a component, a local component with a library or kit name (not a `lazy()` or `dynamic()` wrapper that loads one, nor a Next.js route file's default-exported `Page`, such as `export default function Page()` in `app/**/page.tsx`), styled-components and other CSS-in-JS, a `<style>` block, inline style that sets colour, spacing or type, colour literals, and hand-written timers, wei conversions and address shortening (reported once, on the outermost template literal or `+` chain that holds it), under `kleros-ui/no-styled-components`, `kleros-ui/no-restricted-syntax` and `kleros-ui/no-restricted-imports`, so an app's own `no-restricted-syntax` and `no-restricted-imports` options keep working; an `eslint-disable` comment that names the core id does not silence the preset, and `ui:check` names each such comment. Its Tailwind class rules (palette colours, `dark:` colour overrides, off-scale spacing, radius, font size and weight, arbitrary colours) need `eslint-plugin-better-tailwindcss` 4 or later, an optional peer dependency, and are skipped without it; when it is installed but does not load, they are off too, and the preset prints one warning with the first line of the error. `eslint` itself is an optional peer dependency too (`>=8.26`; ESLint 8.0 to 8.25 cannot run the flat config `ui:check` uses).
- Agent guide: the package ships `agent/AGENTS.md`, the guide for AI coding agents (setup, Tailwind only, themes, existing apps), `agent/LOOK.md` (which token goes where), `agent/NEW-COMPONENT.md`, `agent/REVIEW.md` (a five-part checklist for pull request reviewers, which names the branch files that `ui:check` runs and sends an outside pull request's check to a CI job without secrets or a throwaway container), and `agent/CATALOG.md` with `agent/catalog.json`, which list all 43 core components, the kit and the known gaps, each with its intent words and when to use it. `recipes/` holds three example screens (`vote-form.tsx` tells a wallet rejection, viem's `UserRejectedRequestError` or code 4001 on the error or its cause, apart from other failures and shows the error's short message), and `agent/templates/` the files `kleros-ui new` writes.
- Story types: `@kleros/ui-components-library/story-types` exports minimal `Meta` and `StoryObj` types, so an app's stories type-check without Storybook installed.
- CLI: the `kleros-ui` command. Every command the docs, the agent block and the CLI's messages give is `npx -p @kleros/ui-components-library kleros-ui …`, so npx never looks up the unscoped `kleros-ui` name on the npm registry. `create` copies the starter app (`templates/poc`: Vite, React 18, Tailwind 4.1.17 or later, ESLint and this library's CSS; its `src/App.tsx` lays out with kit `Page`, `Stack` and `Inline`), sets the library version, installs and runs `init`. `init` sets up an existing app, in the app's own folder (it refuses a workspace root: a `package.json` with a non-empty `workspaces` list, or a `pnpm-workspace.yaml` with a `packages:` list): a block in `AGENTS.md` that points coding agents at the guide, `kleros-ui.json`, the `ui:check` and `ui:baseline` scripts, and `kleros-ui.eslint.config.mjs` (`.mts` for a `.ts` or `.mts` app config), the app's own lint config plus the preset, which only those two scripts lint with (the app's `eslint.config.*` stays as it was, so its editor, lint script and pre-commit hook do not report the preset's rules on existing code). The CLI writes no file through a symbolic link that leads out of the app's own files (outside its folder, into its `node_modules`, or to nothing), and `init`, `create`, `new` and `theme` check every file before writing the first. `new` scaffolds a component and registers it with its intent words; in an app with Storybook its stories include a Dark story that sets the `dark` class on `<html>`. `check` (`npm run ui:check`) runs the type-check, the lint, the CSS scan and the registry check, and the starter's build runs `check --build` first. `css` scans the app's stylesheets, `theme` writes the one theme file where an app sets its own token values, `baseline` records an existing app's findings so that only new code is held to the rules (it records nothing while a folder in `cssDirs` is missing), and `sync` updates the agent block. `check` and `baseline` lint `src/`, or, in an app with no `src/` (a Next.js `app/` router), those of `app/`, `pages/`, `components/`, `lib/`, `hooks/` and `utils/` that are there; `"lintDirs"` in `kleros-ui.json` sets the folders, `init` passes them to the preset as `files`, and `check` prints them. `init` run again keeps the `cssEntry` and `files` that the lint config it wrote passes to the preset in step with `kleros-ui.json`, and says what it changed; `check` names a lint config whose copy differs. `init` run again leaves the Cursor rule alone once it is there, edited front matter and CRLF line endings included. `create` into a `"type": "commonjs"` package writes the starter's Vite config as `vite.config.mts` (next to `eslint.config.mjs`). With no `npm` or `npx` in PATH, `create`, `check` and `baseline` exit 1 with one line that names the command (`could not start npx (ENOENT)`), not a stack or a hint about the library spec. `new` records `importPath` from `src/` (`./ui/<Name>` for `src/ui`), or from the app root when `componentsDir` is outside `src/`. The `index.html` scan reads a `<style>` with no `</style>` as a block to the end of the page, and a page of unclosed tags in linear time.
- CLI: `init` warns, and `ui:check` fails setup, when the `react` or `react-dom` that the app's copy of the library resolves is not React 18, or the app's `package.json` asks for a range without 18: Yarn 4 and pnpm install React 19 with only a peer warning (the `react` peer entry under Fixed).
- CLI: `ui:check` notes an `AGENTS.md` block from another release of the installed major, so a library update does not fail CI until someone runs `sync`, and fails on a block from another major, whose rules can name what the installed major does not have. The README and the guide say to run `sync` after each update.
- CLI: `ui:check`, `check --build` and `ui:baseline` fail while `eslint-plugin-better-tailwindcss` does not resolve from the app's copy of the library or fails to load, since the lint preset's Tailwind class rules are off without it; `init` says so.
- CLI: `sync` and `init` refuse an `AGENTS.md` with a second `kleros-ui:start` marker before the first end marker, naming both lines and writing nothing. A marker counts only at the start of a line (up to three spaces in) and outside a code fence, so one quoted in inline code or a fenced example is the app's own text: `sync` leaves it as it is and rewrites the real block, and `ui:check` reads the real block's release.
- CLI: in an app with a theme file (`kleros-ui theme` writes it and records it as `"theme"` in `kleros-ui.json`), `ui:check` fails on an import of the library's `theme.css` under a `layer()`, media or `supports()` condition, or inside an `@layer`, `@media` or `@supports` block, in the Tailwind entry or a stylesheet that imports Tailwind itself. Out of `@layer base`, the library's values can undo the app's theme or its dark values. The plain import the guide writes, and Tailwind's `theme(static)` or `theme(inline)` option, are no finding.

### Changed

- Types and description: the first line of `ui-components-library.d.ts`, `lib/index.d.ts` and each kit type file, and the package description, point coding agents at `agent/AGENTS.md` and `agent/CATALOG.md`. They name no command: every app that updates gets these files, and the guide's Start says how to set an app up, and to ask the app's team first when its `AGENTS.md` has no kleros-ui block.
- Package: the published `package.json` has no `prepare` script. It ran `husky install`, which sets up this repository's git hooks, and npm listed it as an install script it did not run. `package.json` itself is exported.
- README: Setup step 1 sends a new app to `kleros-ui create` and shows the Tailwind entry with the dark variant. Theme usage sets token values only in the theme file that `npx -p @kleros/ui-components-library kleros-ui theme` writes, inside `@layer base`, where it said to override them anywhere. A new section, "Starting a new app, and AI agents", names the starter, `init`, the agent guide and the reviewers' checklist. Setup no longer has the "Apps without Tailwind" path, which imported only `style.css`: every app styles its UI with Tailwind 4, so an existing app without Tailwind adds it first (`agent/AGENTS.md`, "Existing apps"). Peer Dependencies, where it said "Tailwind CSS 4+", says the core needs Tailwind 4 (`^4.0.11`) and the kit and the lint preset 4.1.17 or later, and Setup names the same floor for the kit.
- Docs: the README's first section also names the existing-app setup (`npx -p @kleros/ui-components-library kleros-ui init` once, before writing UI), beside the new-app `create`.
- Package: `exports["."]` lists `types` before `import`.

### Fixed

- Box passes every prop except `className` to its element (`id`, `role`, `aria-*`, handlers), where it dropped all but `children` and `className`.
- BigNumberField reads a leading `.` as `0.` (and `-.` as `-0.` where the field can go below 0), so typing `.5` gives 0.5. The field showed `NaN` and reported `NaN` to `onChange`, and a controlled field kept 5 for `.5`.
- BigNumberField no longer changes the text being typed when it formats the field after 3 seconds without typing: the decimal point, trailing zeros and the sign stay, and only grouping is added. `1.`, `1.0` or `2.50`, a pause, then a digit gave 15, 15 or 2.53; they now give 1.5, 1.05 and 2.503.
- BigNumberField refuses a lone `-` when `minValue` is 0 or more, and a negative zero (`-.`, `-0`, `-0.`) when it is 0, where the field showed `-` while the app kept the last amount, or `-0.` for 0. A refused `-` over formatted text such as `1,000` leaves the field editable, and a `minValue` that does not parse counts as no minimum.
- CircularProgress no longer renders a stray `0` next to the label at 0%.
- CircularProgress keeps a caller's `aria-label` instead of replacing it with the percentage.
- Timeline keeps its titles, parties and dates inside its box: the text wraps within the half of the box beside the spine, where it ran out of any box narrower than about twice the text. A word wider than that half, such as a full address, a transaction hash or a long compound word, wraps too. The spine stays centred, and rows whose text already fits look the same. CustomTimeline is unchanged.
- Timeline no longer widens the page: its shifted rows reached half the box past one edge (the right with `rightSided`), so a phone could scroll sideways into empty space. The list clips that horizontal overflow (`overflow-x: clip`), with no visible change.
- Steps (horizontal): below `lg`, the first step's title aligns to its bullet's left edge and the last step's title to its bullet's right edge, so neither hangs outside the list. Titles between them, and a single step's title, stay centred under their bullets.
- Package: `react`, `react-dom` and `react-is` are `^18` peer dependencies only, no longer also dependencies. A React 19 app now stops at `npm install` with a peer-dependency error (ERESOLVE), where it installed a second React and rendered a blank page; Yarn 4 (YN0060) and pnpm print peer warnings and install anyway. React 19 is not supported yet.
- Package: `react/jsx-runtime` and `react/jsx-dev-runtime` are external, so the build no longer carries React 18's JSX runtime, which threw on import under React 19 (`Cannot read properties of undefined (reading 'ReactCurrentOwner')`). React 19 is still not supported: the peer range stays `^18`.

## [3.10.0] - 2026-10-15

### Breaking changes

None.

### Added

- Theme: ten colours from kleros-v2, in light and dark and as Tailwind utilities: `DarkPurple`, `VioletPurple`, `LavenderPurple`, `WhiteLowOpacitySubtle`, `WhiteLowOpacityStrong`, `BlackLowOpacity`, `SkeletonBackground`, `SkeletonHighlight`, `PaleCyan`, `LimeGreen` ([#93](https://github.com/kleros/ui-components-library/issues/93)).

### Changed

- DropdownSelect and Tabs call a caller's `onSelectionChange`, and Slider calls a caller's `onChange`. These props were accepted but ignored before ([#90](https://github.com/kleros/ui-components-library/issues/90)).
- Tabs: `defaultSelectedKey` selects that tab. Before, it only moved the underline ([#90](https://github.com/kleros/ui-components-library/issues/90)).
- FileUploader: the info icon uses the message's text colour, and every message icon is centred on the first line of the message. The message text sits 1px lower ([#92](https://github.com/kleros/ui-components-library/issues/92)).

### Fixed

- DropdownSelect and DropdownCascader keep a caller's `aria-label` instead of replacing it with "Select", and no longer repeat a visible label in the accessible name ([#96](https://github.com/kleros/ui-components-library/issues/96)).
- Tabs: the underline, label colour and icon follow the selected tab for default, controlled and clicked selection ([#90](https://github.com/kleros/ui-components-library/issues/90)).
- DropdownCascader: changing a controlled `selectedKey` moves the highlighted item in the open tree ([#90](https://github.com/kleros/ui-components-library/issues/90)).
- BigNumberField: a controlled field keeps the text being typed when its value echoes back through `onChange` (`1.05`, Backspace gives `1.0`), and `value=""` shows an empty field instead of `NaN` ([#97](https://github.com/kleros/ui-components-library/issues/97)).
- Timeline and CustomTimeline: the bullet is centred on its title, there is no connector above the first bullet, and the bullet stays centred when the title wraps or resizes ([#100](https://github.com/kleros/ui-components-library/issues/100)).
- FileViewer: the scroll container uses the library's thin scrollbar ([#94](https://github.com/kleros/ui-components-library/issues/94)).
